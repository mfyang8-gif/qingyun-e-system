## 1. 项目概述

### 1.1 项目背景

高校班级日常管理中存在以下痛点：

- **信息过载**：群消息量大、分类混乱，重要通知易被淹没
- **效率低下**：作业收集与提醒依赖人工操作，班委工作负担重
- **数据分散**：学生个人成长记录分散在各个平台,难以系统化沉淀
- **求职困难**：缺乏个人能力的客观评估，简历制作缺乏针对性指导

本项目旨在通过微信小程序 + Web 管理端的组合，借助 NapCat 框架实现群消息自动接收与处理，结合 AI 技术完成消息归纳、个人画像生成与简历诊断，构建面向高校班级的智能信息管理平台。

### 1.2 项目目标

**核心目标**：
- 实现多班级群消息的自动接收、AI 归纳与分类展示，支持班委人工校正
- 实现作业布置、收集与自动提醒的闭环管理
- 沉淀个人荣誉、履历等成长数据，结合行为分析生成个人画像报告
- 基于个人画像与职业意向，提供 AI 简历诊断与优化建议
- 提供 Web 管理端，支持班委管理与管理员监控

**可量化指标**：

- 班委消息整理时间减少 80%
- 作业提交率提升 30%
- 学生简历质量评分提升 40%
- 系统可用性达到 99%

### 1.4 目标用户

- **主要用户**：在校大学生（18-25 岁），熟悉微信小程序操作
- **次要用户**：班委（学生干部），需要管理班级事务
- **管理用户**：系统管理员（学校信息中心或外包团队），负责系统运维

## 3. 功能需求

### 3.1 账号与班级管理模块

#### 3.1.1 用户登录与身份认证

本系统采用**微信授权登录 + 学号身份认证**的两步机制，无需传统注册流程。

**登录流程：**

```
用户打开小程序
↓
微信授权登录（获取 openid）
↓
判断该 openid 是否已完成身份认证
├─ 已认证 → 直接进入主页
└─ 未认证 → 进入身份认证页↓
    输入学号 + 选择所属班级
    ↓
    与管理员导入的名单比对
    ├─ 匹配成功 → 绑定 openid，认证完成，进入主页
    │（角色依据名单自动赋予：普通学生/班委）
    └─ 匹配失败 → 提示"学号或班级信息不匹配，请联系管理员"
                  允许重试 3 次，超过后锁定 24 小时
```

**功能需求：**

- **FR-001**：小程序端使用微信授权登录，获取用户 openid，无需账号密码注册
- **FR-002**：首次登录用户需完成身份认证：输入学号并选择所属班级
- **FR-003**：系统将输入的学号与班级组合，与管理员预先导入的名单进行比对；完全匹配则认证成功，否则认证失败并提示错误信息
- **FR-004**：认证成功后，系统将用户 openid 与名单中对应记录绑定，后续登录无需重复认证
- **FR-005**：用户角色（普通学生/班委）依据导入名单中的角色字段自动赋予，无需手动申请或审核
- **FR-006**：Web 端（班委/管理员）采用账号密码登录，账号由管理员在后台创建
- **FR-007**：学号认证失败后允许重试 3 次，超过后该 openid 锁定 24 小时，防止恶意尝试
- **FR-008**：用户更换手机/微信后，使用新 openid 登录时需重新进行学号认证，系统自动解绑旧 openid
- **FR-009**：提供"申诉通道"入口，认证失败用户可提交申诉（附带学号、姓名、班级、联系方式），管理员审核后手动绑定

#### 3.1.2 班级名单导入（管理员）

- **FR-010**：管理员可在 Web 端为指定班级导入学生名单，支持 Excel 格式文件上传
- **FR-011**：名单文件标准字段包括：学号（必填）、姓名（必填）、班级（必填）、角色（必填，学生/班委）、邮箱（选填）
- **FR-012**：系统提供标准模板下载，模板中包含字段说明与示例数据
- **FR-013**：导入时系统自动校验数据格式，对以下异常逐行提示：
 - 缺失必填字段
 - 学号重复（学号全校唯一）
 - 邮箱格式错误
 - 角色字段非法值
- **FR-014**：校验通过的数据支持部分导入，异常数据导出为错误报告供管理员修正后重新导入
- **FR-015**：管理员可对已导入名单进行增删改操作，修改角色字段后实时生效（如将某学生升级为班委）
- **FR-016**：若某学号已完成微信绑定，管理员修改其角色后，该用户下次进入小程序时权限自动更新
- **FR-017**：管理员可查看每个班级名单的认证状态，区分"已认证（已绑定微信）"与"未认证"两种状态
- **FR-018**：支持批量导出班级名单，包含认证状态、最后登录时间等信息

#### 3.1.3 班级注册与群号绑定（管理员）

- **FR-019**：管理员可在 Web 端创建新班级，填写班级名称、所属院系、年级、专业等基本信息
- **FR-020**：管理员为每个班级配置对应的 NapCat 账号（主账号 + 备用账号），填写账号凭证（加密存储）
- **FR-021**：支持一个班级绑定多个群聊，每个群聊可设置分类标签（如"班级通知群""课程群""活动群"）
- **FR-022**：管理员可随时调整群号绑定关系，新增或解绑群聊
- **FR-023**：系统自动检测 NapCat 账号是否成功加入绑定的群聊，未加入的群聊标记为"待加入"状态并告警
- **FR-024**：支持批量导入班级信息（Excel 格式），包含班级基本信息与群号绑定关系

### 3.2 智能群消息处理模块

#### 3.2.1 消息接收

- **FR-025**：通过 NapCat 框架，每个班级专属账号自动接收所绑定群聊的消息
- **FR-026**：支持接收以下消息类型：
 - 文本消息
 - 图片消息（自动下载并存储至对象存储）
 - 文件消息（自动下载并存储至对象存储）
 - 语音消息（暂不处理，标记为"未支持类型"）
 - 视频消息（暂不处理，标记为"未支持类型"）
- **FR-027**：消息接收后实时写入数据库，记录以下元数据：
 - 消息 ID（唯一标识）
 - 来源群聊（群号）
 - 发送者（QQ 号/昵称）
 - 消息类型
 - 消息内容（文本/文件 URL）
 - 接收时间戳
 - 是否 @ 特定人
- **FR-028**：消息接收失败时（网络异常、NapCat 掉线等），系统自动重试 3 次，仍失败则记录错误日志并告警
- **FR-029**：消息撤回后，系统标记该消息为"已撤回"状态，但保留原始内容用于审计

#### 3.2.2 AI 自动归纳与分类

- **FR-030**：对接收到的文本消息调用第三方 AI API（如 OpenAI、文心一言、通义千问）进行文本归纳
- **FR-031**：图片消息先通过 OCR 提取文字，再进行归纳；文件消息先解析内容（支持 PDF、Word、Excel），再进行归纳
- **FR-032**：AI 归纳输出以下结构化信息：
 - 消息摘要（50 字以内）
 - 分类标签（单选）
 - 关键词（多个）
 - 置信度（0-1 之间的浮点数）
- **FR-033**：预设分类标签包括：
 - 通知公告（学校/学院/班级通知）
 - 作业相关（作业布置、提交提醒）
 - 活动报名（讲座、比赛、社团活动）
 - 荣誉评选（奖学金、评优评先）
 - 课程安排（选课、调课、考试安排）
 - 日常聊天（闲聊、表情包、无关内容）
 - 其他
- **FR-034**：置信度低于 0.7 的消息标记为"待校正"状态，推送至班委审核队列
- **FR-035**：AI 归纳失败或超时（超过 10 秒）时，系统自动降级：将消息标记为"待校正"，不阻塞后续消息处理
- **FR-036**：支持消息去重：相同内容（文本相似度 > 90%）的消息在 24 小时内只归纳一次，后续重复消息直接引用首次归纳结果

#### 3.2.3 消息中心展示

- **FR-037**：小程序端为每个班级提供独立的消息中心页面
- **FR-038**：支持按分类标签筛选消息，支持关键词搜索
- **FR-039**：消息列表展示以下信息：
 - 消息摘要
 - 分类标签（带颜色标识）
 - 发送者昵称
 - 发送时间
 - 未读/已读状态
- **FR-040**：点击消息可查看原始消息详情，包括完整内容、图片/文件附件、来源群聊
- **FR-041**：支持消息收藏功能，收藏的消息在"我的收藏"中单独展示
- **FR-042**：支持消息标记已读/未读，未读消息在消息中心入口显示红点提示
- **FR-043**：重要消息（通知公告、作业相关）支持置顶显示
- **FR-044**：记录每个用户对各类消息的点击行为（消息 ID、用户 ID、点击时间），用于后续个人画像分析
- **FR-045**：消息中心支持下拉刷新，自动加载最新消息

#### 3.2.4 班委人工校正（Web 端）

- **FR-046**：班委可在 Web 端查看"待校正"消息队列，按时间倒序排列
- **FR-047**：班委可修改消息的分类标签、摘要内容、关键词，并确认校正
- **FR-048**：校正记录保留操作人、操作时间、修改前后内容，用于审计追溯
- **FR-049**：班委可手动将任意消息重新归类或标记为"忽略"（不在消息中心展示）
- **FR-050**：班委可批量处理相似消息（如多条重复通知），一次性修改分类标签
- **FR-051**：校正后的消息实时同步至小程序端消息中心

### 3.3 日常事务处理模块

#### 3.3.1 作业布置与管理

- **FR-052**：班委可在小程序端或 Web 端发布作业，填写以下信息：
 - 作业标题（必填，50 字以内）
 - 详细说明（必填，支持富文本）
 - 截止时间（必填，精确到分钟）
 - 提交方式（文件上传/文字填写/链接提交）
 - 附件上传（选填，支持文档、图片、压缩包等）
 - 提醒时间节点（选填，默认为截止前 24 小时）
- **FR-053**：作业发布后，系统自动在对应班级群发送作业通知消息（通过 NapCat 账号）
- **FR-054**：学生可在小程序端查看本班作业列表，支持按状态筛选：
 - 未截止（按截止时间升序排列）
 - 已截止
 - 已提交
- **FR-055**：学生可在线提交作业：
 - 文件上传（支持多文件，单文件不超过 50MB）
 - 文字填写（支持富文本）
 - 链接提交（如 GitHub 仓库、在线文档等）
- **FR-056**：作业提交后，学生可修改/重新提交，但需在截止时间前完成
- **FR-057**：班委可在 Web 端查看作业提交情况：
 - 已提交人数/总人数
 - 未提交学生名单
 - 提交时间分布图
- **FR-058**：班委可批改作业，填写评分（0-100 分）与评语
- **FR-059**：班委可导出作业提交情况报表（Excel 格式）
- **FR-060**：班委可编辑或删除已发布的作业，删除前需二次确认
- **FR-061**：支持作业分组提交（如小组作业），小组成员共同提交一份作业

#### 3.3.2 自动提醒推送

- **FR-062**：作业发布后，系统按预设节点自动触发提醒，由 NapCat 账号在班级群发送提醒消息
- **FR-063**：默认提醒时间节点为截止前 24 小时，班委可自定义为以下选项：
 - 截止前 48 小时
 - 截止前 24 小时
 - 截止前 12 小时
 - 截止前 1 小时
 - 支持多选
- **FR-064**：提醒消息内容包含：
 - 作业名称
 - 截止时间
 - 未提交人数（可选，班委可关闭此项）
 - 作业详情链接（跳转至小程序）
- **FR-065**：提醒发送失败时（NapCat 掉线、群消息发送失败等），系统自动重试 3 次，仍失败则记录错误日志并告警管理员
- **FR-066**：提醒发送记录可在 Web 端查看，包含发送时间、发送状态、失败原因
- **FR-067**：支持手动触发提醒，班委可在 Web 端点击"立即提醒"按钮，系统立即发送提醒消息

#### 3.3.3 荣誉记录

- **FR-068**：学生可在小程序端录入个人荣誉，填写以下信息：
 - 荣誉名称（必填）
 - 颁发机构（必填）
 - 获奖时间（必填）
 - 荣誉级别（校级/省级/国家级/国际级）
 - 证明材料上传（选填，支持图片、PDF）
- **FR-069**：班委可录入班级荣誉，填写以下信息：
 - 荣誉名称（必填）
 - 获奖时间（必填）
 - 参与成员（多选，从班级名单中选择）
 - 证明材料上传（选填）
- **FR-070**：个人荣誉数据自动关联至该用户的个人画像数据池
- **FR-071**：班级荣誉数据在班级主页展示，并可作为班级成员画像的辅助参考
- **FR-072**：学生可编辑或删除已录入的个人荣誉
- **FR-073**：班委可审核学生提交的个人荣誉，审核通过后才计入画像数据

### 3.4 个人画像分析模块

#### 3.4.1 数据采集

**行为数据（自动采集）：**

- **FR-074**：系统自动采集以下行为数据用于画像分析：
 - 用户对各类消息的点击频率与偏好分类
 - 作业提交及时率（提交时间 vs 截止时间）
 - 个人荣誉记录（数量、级别、类型）
 - 小程序使用频率与活跃时段

**主动上传信息：**

- **FR-075**：用户可主动上传以下结构化信息：
 - **个人履历**：教育经历（学校、专业、时间）、在校经历（社团、学生组织、志愿活动）
 - **实习经历**：公司、岗位、时间、工作描述
 - **项目经历**：项目名称、角色、技术栈、成果描述
 - **技能标签**：自评技能（如编程语言、设计工具、语言能力等），支持自定义标签

**问卷调查：**

- **FR-076**：系统提供问卷调查，内容涵盖以下维度：
 - 职业兴趣（技术、管理、设计、市场等）
 - 能力自评（沟通能力、领导力、学习能力等）
 - 发展方向（考研、就业、创业、出国等）
 - 性格特质（MBTI、大五人格等）
- **FR-077**：问卷在用户首次完成身份认证后推送一次（必填），后续每学期推送一次（选填），用户也可随时主动填写
- **FR-078**：问卷结果纳入画像分析，权重可配置

#### 3.4.2 AI 画像生成

- **FR-079**：综合行为数据、主动上传信息与问卷结果，调用第三方 AI API 生成个人画像报告
- **FR-080**：画像报告包含以下维度：
 - **兴趣偏好分析**：基于消息点击行为，分析用户对不同类型信息的关注度（如学术、活动、技术、文艺等）
 - **能力标签**：基于荣誉、项目、实习，提取用户的核心能力（如编程能力、设计能力、组织能力等）
 - **综合素质评估**：基于作业提交及时率、活跃度、荣誉数量等，评估用户的责任心、自律性、积极性
 - **职业发展方向建议**：基于问卷结果与能力标签，推荐适合的职业方向（如前端开发、产品经理、数据分析等）
- **FR-081**：画像报告以可视化形式展示：
 - 雷达图（能力维度）
 - 标签云（兴趣偏好）
 - 柱状图（综合素质评分）
 - 文字描述（职业发展建议）
- **FR-082**：画像报告仅本人可见，管理员可查看脱敏汇总数据（不包含姓名、学号等个人信息）
- **FR-083**：用户可手动触发画像更新，系统也定期自动更新（每月 1 次）
- **FR-084**：画像置信度计算逻辑：
 - 数据完整度占比 60%（行为数据 20%、主动上传信息 30%、问卷结果 10%）
 - 数据时效性占比 20%（近 3 个月数据权重更高）
 - 数据一致性占比 20%（多维度数据交叉验证）
- **FR-085**：若用户数据不足（置信度 < 0.5），系统提示"当前个人画像置信度较低，请及时补充相关材料"，并给出具体补充建议（如"缺少实习经历""未填写问卷"等）
- **FR-086**：支持画像历史版本查看，用户可对比不同时间点的画像变化，查看成长轨迹

- **FR-087**：用户可基于个人画像数据一键生成简历草稿
- **FR-088**：系统提供多套简历模板（至少 5 套），分类如下：
 - 技术类（适合开发、测试、运维等岗位）
 - 管理类（适合产品、运营、项目管理等岗位）
 - 设计类（适合 UI/UX、平面设计等岗位）
 - 通用类（适合多种岗位）
 - 学术类（适合科研、考研等方向）
- **FR-089**：生成的简历内容自动填充以下信息：
 - 个人信息（姓名、联系方式、邮箱）
 - 教育经历
 - 实习经历
 - 项目经历
 - 荣誉奖项
 - 技能标签

- **FR-092**：用户可上传已有简历（支持 PDF、Word 格式），系统自动解析内容

 - **优势分析**：简历中的亮点与优势

- **FR-095**：诊断报告以结构化形式展示，支持导出为 PDF
- **FR-096**：用户可查看历史诊断记录，对比不同版本简历的评分变化
- **FR-097**：系统提供"一键优化"功能（可选），基于诊断建议自动生成优化后的简历版本供用户参考

## 5. 非功能需求

### 5.1 性能需求

- **NFR-001**：消息接收延迟不超过 3 秒（从群消息发送到系统接收）
- **NFR-002**：AI 归纳响应时间不超过 10 秒（单条消息）
- **NFR-003**：小程序端页面加载时间不超过 2 秒（首屏）
- **NFR-004**：Web 端页面加载时间不超过 3 秒（首屏）
- **NFR-005**：支持单班级 500 人规模，系统总用户量 10 万人
- **NFR-006**：支持单日消息处理量 10 万条
- **NFR-007**：数据库查询响应时间不超过 500ms（95% 请求）

### 5.2 可用性需求

- **NFR-008**：系统可用性达到 99%（年停机时间不超过 87.6 小时）
- **NFR-009**：NapCat 账号掉线后 5 分钟内自动重连
- **NFR-010**：关键服务（消息接收、作业提醒）支持故障自动切换（主备账号）
- **NFR-011**：数据库支持每日自动备份，备份保留 30 天

### 5.3 安全需求

- **NFR-012**：用户密码采用 bcrypt 加密存储，加盐轮次不少于 10
- **NFR-013**：NapCat 账号凭证采用 AES-256 加密存储
- **NFR-014**：API 接口采用 JWT 认证，token 有效期 2 小时
- **NFR-015**：敏感操作（删除作业、修改角色）需二次确认
- **NFR-016**：所有 API 请求需记录操作日志（用户 ID、操作类型、时间戳、IP 地址）
- **NFR-017**：文件上传需校验文件类型与大小，防止恶意文件上传
- **NFR-018**：防止 SQL 注入、XSS 攻击、CSRF 攻击

### 5.4 兼容性需求

- **NFR-019**：小程序端兼容微信版本 7.0 及以上
- **NFR-020**：Web 端兼容 Chrome 90+、Firefox 88+、Safari 14+、Edge 90+
- **NFR-021**：移动端 Web 适配 iOS 13+ 和 Android 8+

### 5.5 可维护性需求

- **NFR-022**：代码遵循统一编码规范（如 ESLint、Prettier）
- **NFR-023**：核心模块单元测试覆盖率不低于 80%
- **NFR-024**：提供完整的 API 文档（Swagger/OpenAPI）
- **NFR-025**：提供系统部署文档与运维手册
- **NFR-026**：关键业务逻辑需添加详细注释

### 5.6 扩展性需求

- **NFR-027**：支持横向扩展（增加服务器节点）
- **NFR-028**：消息处理模块支持异步队列（Redis/RabbitMQ）
- **NFR-029**：AI API 调用支持多厂商切换（OpenAI、文心一言、通义千问等）
- **NFR-030**：简历模板支持动态配置与新增

## 6. 异常场景处理

### 6.1 NapCat 账号异常

| 异常场景       | 处理策略                                                     |
| -------------- | ------------------------------------------------------------ |
| 账号掉线       | 自动重连（最多 3 次），失败后切换备用账号，并告警管理员      |
| 账号被封禁     | 立即告警管理员，停止该班级消息接收，提示班委更换账号         |
| 群消息发送失败 | 重试 3 次，仍失败则记录错误日志并告警，不阻塞其他消息处理    |
| 未加入绑定群聊 | 标记为"待加入"状态，每小时检测一次，超过 24 小时未加入则告警 |

### 6.2 AI 服务异常

| 异常场景     | 处理策略                                               |
| ------------ | ------------------------------------------------------ |
| API 调用超时 | 超时时间设为 10 秒，超时后降级处理：标记消息为"待校正" |
| API 返回错误 | 记录错误日志，降级处理：标记消息为"待校正"             |
| API 配额耗尽 | 告警管理员，暂停 AI 归纳功能，所有新消息标记为"待校正" |
| 返回结果异常 | 校验返回数据格式，异常则降级处理：标记消息为"待校正"   |

### 6.3 用户操作异常

| 异常场景     | 处理策略                                               |
| ------------ | ------------------------------------------------------ |
| 学号认证失败 | 允许重试 3 次，超过后锁定 24 小时，提供申诉通道        |
| 文件上传失败 | 提示用户重试，记录错误日志（文件大小、格式、网络状态） |
| 作业提交超时 | 截止时间后禁止提交，提示"已超过截止时间"               |
| 重复提交作业 | 覆盖旧提交记录，保留提交历史用于审计                   |
| 简历解析失败 | 提示用户"简历格式不支持，请上传 PDF 或 Word 格式"      |

### 6.4 系统故障

| 异常场景         | 处理策略                                               |
| ---------------- | ------------------------------------------------------ |
| 数据库连接失败   | 自动重连（最多 3 次），失败后返回 503 错误，告警管理员 |
| Redis 连接失败   | 降级为直接查询数据库，记录错误日志并告警               |
| 对象存储服务异常 | 文件上传失败时提示用户重试，记录错误日志并告警         |
| 服务器宕机       | 负载均衡自动切换至备用节点，告警管理员                 |

## 9. 风险评估

### 9.1 技术风险

| 风险项                 | 风险等级 | 影响                           | 应对措施                                             |
| ---------------------- | -------- | ------------------------------ | ---------------------------------------------------- |
| NapCat 账号频繁掉线    | 高       | 消息接收中断，影响核心功能     | 配置主备账号，自动切换；优化重连机制；监控告警       |
| AI API 调用配额耗尽    | 中       | 消息归纳功能暂停，依赖人工校正 | 设置配额告警阈值；准备多厂商 API 备用；优化调用频率  |
| 消息量激增导致性能瓶颈 | 中       | 系统响应变慢，用户体验下降     | 引入消息队列异步处理；数据库读写分离；增加服务器节点 |
| 第三方服务不稳定       | 中       | 文件上传失败、OCR 识别失败等   | 设置超时与重试机制；降级处理；选择稳定的服务商       |

### 9.2 业务风险

| 风险项            | 风险等级 | 影响                           | 应对措施                                                     |
| ----------------- | -------- | ------------------------------ | ------------------------------------------------------------ |
| 用户隐私泄露      | 高       | 法律风险，用户信任度下降       | 敏感数据加密存储；严格权限控制；定期安全审计                 |
| AI 归纳结果不准确 | 中       | 用户对系统信任度下降           | 提供班委人工校正功能；持续优化 AI 模型；收集用户反馈         |

| 用户活跃度低      | 低       | 个人画像数据不足，置信度低     | 引导用户补充信息；定期推送问卷；提供激励机制（如积分、勋章） |

## 附加说明

### 关键设计决策

1. **为什么采用学号认证而非传统注册？**

 - 简化用户操作流程，降低使用门槛
 - 确保用户身份真实性，与学校名单一一对应
 - 避免重复注册与账号混乱

2. **为什么每个班级使用独立 NapCat 账号？**

 - 降低单点故障风险（一个账号被封不影响其他班级）
 - 便于权限隔离与数据管理
 - 符合 QQ 群管理规范（避免单账号加入过多群聊被限制）

3. **为什么消息归纳采用 AI + 人工校正的混合模式？**

 - AI 归纳可大幅减少人工工作量（80% 以上消息自动处理）
 - 人工校正保证关键消息准确性，提升用户信任度
 - 校正数据可用于持续优化 AI 模型

4. **为什么个人画像需要多维度数据？**

 - 单一数据源（如仅行为数据）容易产生偏差
 - 多维度交叉验证可提升画像准确性与置信度
 - 用户主动上传信息体现真实意愿，权重更高

5. **为什么简历诊断需要结合个人画像？**

 - 个人画像提供客观能力评估，避免简历"注水"
 - 基于画像的诊断更具针对性，建议更实用
 - 帮助用户发现自身优势与不足，提升求职竞争力

### 后续扩展方向

3. **校友网络**：毕业生信息留存，构建校友资源网络
